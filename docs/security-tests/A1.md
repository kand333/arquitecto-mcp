# A1 — Editor sin autenticación ni verificación de Origin/Host

**Hallazgo de la auditoría (alta):** el WebSocket `/ws` y los endpoints HTTP del editor no tienen autenticación ni verificación de Origin/Host. Sin token se obtiene lectura y escritura completas, así que el modo «solo lectura» se elude. Evidencia en el upstream: `packages/server/src/live.ts:341-351, 378-409, 247-255`; `tools.ts:276` sugiere `0.0.0.0`.

**Tests:** `packages/server/src/live.test.ts`, bloque `A1 — editor exige token, Origin y Host locales`.

## Fix

- `live.ts`: token del propietario aleatorio por arranque (`randomBytes(24)`, solo en memoria). WS: propietario = escritura, link compartido = solo lectura, otro o ausente = cierre `4001`. `verifyClient` exige Host `localhost|127.0.0.1:<port>` y Origin igual o ausente (cliente no-browser) → `403`. Middleware Hono: Host local en todo HTTP (anti DNS-rebinding) → `403`. `/share` y `/share/rotate` solo propietario; `/plan` y `/so-sanh` propietario o link compartido → si no, `401`. Escucha fija en `127.0.0.1` (se eliminan la opción `host` y `ARQUITECTO_HOST`). Comparación de tokens en tiempo constante.
- `tools.ts`: `editor_open` abre `live.editorUrl()` (con token); se quita la sugerencia de `0.0.0.0`; el enlace de `variant_compare` lleva token.
- Web (`main.ts`, `plan2d.ts`): el token de la URL (`?token=` o `/xem/<token>`) viaja al WS, a `/plan` y a `/share`.
- Tests existentes (`live.test.ts`, `live-e2e.test.ts`) y `cli/smoke.mts`: envían el token; ninguna aserción cambió.
