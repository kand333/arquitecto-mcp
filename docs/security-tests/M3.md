# M3 — project_open acepta cualquier ruta y filtra contenido en el error

**Hallazgo de la auditoría (media):** `project_open` acepta cualquier ruta, y el mensaje de error de `JSON.parse` puede filtrar contenido al agente. Evidencia en el upstream: `store.ts:131-135`, `tools.ts:42-45`.

**Causa raíz:** `store.openProject(file)` resolvía `path.resolve(baseDir, file)` sin confinar, y el mensaje de `JSON.parse` (que en Node incluye un fragmento del archivo) llegaba tal cual al agente vía `fail(e)`.

**Test:** `server/src/store.test.ts`, bloque `M3`.

## Fix

- `store.openProject`: la ruta pasa por `safeJoin(baseDir, file)` (solo dentro de la carpeta del proyecto, sea absoluta o relativa). Se reutiliza el helper de A2, cuyo mensaje pasa a «fuera del directorio permitido».
- `JSON.parse` envuelto: el error es `<ruta> no es JSON válido.`, sin el fragmento del archivo.

Commit conjunto M2+M3: comparten `store.ts` y `store.test.ts`; separarlos dejaba un commit con tests en rojo.
