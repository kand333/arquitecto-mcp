# A2 — IDs sin validación de formato terminan en rutas de archivo

**Hallazgo de la auditoría (alta):** los IDs no tienen validación de formato, y `level.id`/`meta.id` acaban en rutas de archivo. Con `../` se escriben `.svg/.png/.dxf/.pdf/.glb/.ifc` fuera de `.atelier/exports`. Evidencia en el upstream: `core/src/ops/apply.ts:116-122`, `server/src/render/render.ts:85-89`, `render/sheets.ts:59,66`, `tools.ts:604,611,631`, `store.ts:136`.

**Hallazgos adicionales en la inspección:**
- `applyRecord` hace `record[id] = …` sobre un objeto plano: un id `__proto__` (que cumple `^[A-Za-z0-9_-]{1,32}$`) contamina el prototipo.
- `openVariant` también carga un modelo completo desde disco sin pasar por ops.
- `slugify` puede generar `meta.id` de más de 32 caracteres.

**Decisiones del usuario:** regex + lista negra (`__proto__`, `constructor`, `prototype`); `slugify` recorta a 32; al cargar de disco se validan **todos** los IDs; un solo commit.

**Tests:** bloques `A2` en `core/src/ops/apply.test.ts`, `server/src/store.test.ts` y `server/src/safe-path.test.ts`.

## Fix

- `core/src/ids.ts`: `isValidId()` (`^[A-Za-z0-9_-]{1,32}$` y nunca `__proto__`, `constructor` ni `prototype`) y `findInvalidId(project)` (meta.id + todas las entidades).
- `core/src/ops/apply.ts`: `add` en `applyArray`, `applyRecord` (styles/finishes) y `applyAxis` rechaza IDs inválidos con `OPS-02`. `update` ya prohibía cambiar el id; underlay ya exige `"U1"`.
- `server/src/store.ts`: `openProject` y `openVariant` validan todos los IDs antes de usar el modelo (si falla, el proyecto actual no cambia). `newProject` recorta `meta.id` a 32.
- `server/src/safe-path.ts`: `safeJoin(dir, name)` = `resolve` + `startsWith(dir + sep)`. Se usa en `render/render.ts` (antes de crear nada en disco) y en los 5 exportes de `tools.ts` (glb, ifc, pdf, svg, dxf). `render/sheets.ts` no escribe archivos (solo arma `fileBase`), por eso no cambia.

**Desviación de la decisión «truncar slugify»:** `slugify` también nombra las variantes, y `saveVariant` sobrescribe si el slug coincide. Recortarlo pisaría en silencio dos variantes con nombres largos y el mismo prefijo. Se recorta solo `meta.id` en `newProject`; el test de `slugify` se reemplazó por uno sobre `meta.id` (con el código previo también falla: `meta.id` de 39 caracteres).

## Corrección 2026-10-13: barra invertida en Linux

- **Rojo:** el CI de GitHub (Ubuntu) fallaba desde el 2026-10-12 en `safe-path.test.ts > safeJoin acepta nombres simples y rechaza traversal y rutas absolutas` con `AssertionError: "..\x.svg": expected [Function] to throw an error`. En Linux la barra invertida no separa rutas, así que `..\x.svg` era un nombre válido dentro del directorio. En Windows sí se rechazaba, por eso la suite local estaba verde.
- **Fix:** `safeJoin` trata la barra invertida como separador en todos los sistemas (`server/src/safe-path.ts`). Así `..\x.svg` es traversal también en Linux, y las rutas absolutas de Windows (calco, `project_open`) siguen funcionando. Un primer intento que rechazaba toda barra invertida rompía esas rutas: lo detectaron los tests de `underlay_import`.
- **Verde:** `pnpm exec vitest run packages/server/src/safe-path.test.ts` local, y el CI de Linux del PR #2.
